# Phase 9A - Inference Artifact & Pipeline Bridge

This document details the Phase 9A integration of the offline ML baseline (Phase 8) into the live streaming pipeline (Phase 6).

## 1. The Phase 8 Artifact Contract
The offline machine-learning pipeline produces three critical artifacts in the model directory (e.g. `models/baseline_random/`):
- `feature_config.json`: Declares exactly which features the model expects and their exact ordering.
- `preprocessor.joblib`: The fitted `StandardScaler` used to normalize numeric inputs, ensuring live data is transformed using the exact parameters derived from training.
- `<model_name>.joblib`: The trained scikit-learn classifier (e.g., `RandomForest.joblib`).

The `BaselineInferenceEngine` rigorously validates that all three artifacts exist and that the input data dimensionality exactly matches the expected contract.

## 2. The Phase 6 → Phase 8 Bridge (`Phase6toPhase8Bridge`)
The live pipeline (Phase 6) extracts a robust 16-feature behavioural representation (including source-IP contextual states). 
The `Phase6toPhase8Bridge` explicitly converts this dictionary-based 16-feature output into a strictly ordered 13-feature `numpy.ndarray` vector required by the baseline models.

It guarantees that:
- Only expected features are passed forward.
- The feature order perfectly matches `feature_config.json`.
- Missing/`None` values raise explicit errors (no silent zero-filling).

## 3. Distinction: 16 Canonical Features vs 13 ML Baseline Features
**Phase 6 (Canonical Pipeline):** Computes 16 mathematically complete features, including cross-flow contextual data (`src_ip_flow_count`, `src_ip_unique_dst_ips`, `src_ip_unique_dst_ports`) which are vital for detecting distributed scans or floods.
**Phase 8 (ML Baseline):** Uses only 13 features because the external offline CSV datasets (CIC-IDS2018) lack the underlying structural data necessary to faithfully compute those three contextual features.

## 4. How Inference Loads the Model
`BaselineInferenceEngine` is initialized via:
```python
engine = BaselineInferenceEngine(model_dir="models/baseline_random", model_name="RandomForest")
```
It dynamically determines feature requirements from `feature_config.json`, loads the `preprocessor.joblib`, and sets up the classifier. 

Prediction is then invoked via:
```python
result = engine.predict(features_vector)
```
Where `features_vector` is the 13-feature array generated by the bridge. The result is a structured dictionary returning the predicted class label, numeric ID, confidence, and metadata.

## 5. How to Run a Deterministic Inference Test
A complete end-to-end integration test (`test_bridge_integration_success`) is available in `tests/test_bridge_integration.py`. It simulates a valid Phase 6 dictionary output, passes it through the bridge, preprocesses it, and executes the mocked model prediction.

Run tests using:
```bash
.venv\Scripts\python.exe -m pytest tests/test_bridge_integration.py
```

## 6. Omission of Contextual Features
The three omitted features (`src_ip_flow_count`, `src_ip_unique_dst_ips`, `src_ip_unique_dst_ports`) are NEVER fabricated by the bridge. They are cleanly dropped during the hand-off to the ML baseline to ensure absolute mathematical integrity. Future models trained natively on live PCAP datasets (which natively generate context) will consume the full 16-feature vector without requiring truncation by the bridge.
